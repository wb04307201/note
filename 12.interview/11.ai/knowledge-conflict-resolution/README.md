# RAG 检索回三份互相矛盾的文档，怎么处理？——能直接丢给模型自行判断吗

> 一句话定位：**不能**——LLM 面对冲突证据有系统性偏差（多数从众、位置敏感、折中编造、不会自发声明矛盾），会把 2:1 的过时多数当真相。正确解法是显式流水线：**先归因**（时间差/条件差/真冲突）**再仲裁**（规则优先、LLM-as-Judge 兜底），高风险场景显式披露冲突或升级人工。完整深度见 [主模块 知识冲突解决](../../../09.ai-applications/rag/knowledge-conflict-resolution/README.md)。

> **系列定位**：RAG 检索工程面试题（AI 应用岗高频场景题）。考察的不是"会不会拼 Prompt"，而是 **LLM 作为裁判的能力边界** + **冲突归因与仲裁的工程化分层** + **高风险场景的兜底意识**。

---

## 引子：新政上线第一天就答错

```text
用户问："退货运费谁承担？"
Top-K 召回三份文档：
  Doc A（2024 客服 FAQ，第三方转载）："7 天内退货，运费买家承担。"
  Doc B（2025 内部培训材料）：      "7 天内退货，运费买家承担。"
  Doc C（2026 新政公告，即日生效）："15 天内退货，运费商家承担。"
三份都拼进 Prompt，模型按 2:1 多数答"7 天、买家承担"——新政是 15 天、商家承担。
架构师问："直接丢给模型自己判断不行吗？这种矛盾文档该怎么处理？"
```

- **直觉解**："都放进上下文，模型够聪明会自己选"——没意识到 LLM 是 **biased 裁判**，多数票 ≠ 正确票
- **踩坑点**：Doc A/B 看似两个信源，实为同源转载——**伪造多数票**，计票前必须先归并独立信源

**题意边界**：问的是"多份矛盾文档的**裁决机制**"，不是"检索精度优化"——答案核心是归因 + 分层仲裁，不是调 Rerank。

## 一、核心原理

### 1.1 为什么不能直接丢给模型（LLM 裁判的 5 个系统性偏差）

ICLR 2024《Adaptive Chameleon or Stubborn Sloth》实证 + EMNLP 2024 知识冲突综述：

1. **多数从众**：上下文 2:1 的多数派显著带偏答案——哪怕多数是过时转载
2. **位置偏差**：调换文档顺序答案可能翻转；长上下文中间段被忽略（Lost in Middle）
3. **无可信度信息**：模型看不到"转载 vs 官方公告"——元数据不进 Prompt，权威无从判断；检索分数高 ≠ 可信
4. **折中编造**："7-15 天"这种两边都不对的平均化答案（幻觉新来源）
5. **不会自发声明冲突**：默认自信单选，用户不知道背后三份文档打架

> **边界**：不是"LLM 不能参与仲裁"，而是**隐式信任 vs 显式仲裁**的区别——裸拼 Prompt 指望模型自己搞定 ❌；显式检测冲突 → 附元数据 → 要求引证 + 允许"无法裁决" = LLM-as-Judge ✅。

### 1.2 先归因：三种冲突，三种解法

| 冲突类型 | 例子 | 解法 |
|---------|------|------|
| **时间性** | 2024 旧政策 vs 2026 新政 | 入库 `effective_date` 元数据 + pre-filtering，旧版直接出局 |
| **条件性（伪冲突）** | 境内 7 天 / 跨境 15 天，都对 | 澄清条件或**并列呈现**，别删任何一份 |
| **真事实冲突** | 转载错数 / 源数据错误 | 仲裁：时效 > 权威 > 独立信源共识 > LLM-as-Judge > 人工 |

### 1.3 四层防线（越早越便宜）

```text
L1 入库预防：版本/权威元数据 + 转载归并（canonical hash）——最便宜的仲裁
L2 冲突检测：成对 NLI / LLM 事实抽取比对 / Self-Consistency 采样
L3 仲裁：规则优先（时效>权威>共识），LLM-as-Judge 兜底，结果落日志
L4 生成呈现：高置信度直答；伪冲突并列；低置信度显式披露；高风险转人工
```

## 二、代码示例：LLM-as-Judge 仲裁 Prompt 契约

```text
你是证据仲裁器。以下文档对同一问题给出矛盾答案：
[Doc 1] effective_date=2024-03, source=第三方转载, authority_tier=4 ...
[Doc 2] effective_date=2026-01, source=官方公告, authority_tier=1 ...
规则：① 新时效优先 ② 高权威级优先 ③ 必须引用胜出文档原文
     ④ 证据不足以裁决时输出 {"verdict":"undecidable"}，禁止折中编造
输出 JSON：{"verdict": "...", "evidence": "...", "confidence": 0.0-1.0}
```

要点：**元数据必须随文档进 Prompt**（否则模型无从判断权威性）；`confidence < 阈值` 或高风险域 → 走 L4 升级人工，不静默选边。

## 三、面试陷阱

### 陷阱 1："丢给模型自行判断就行"

- **❌ 错误解**："上下文都给全了，模型够聪明"
- **✅ 真相**：多数从众 + 位置偏差 + 折中编造——模型是 biased 裁判。答"隐式信任不行，要显式检测 + 规则仲裁 + Judge 兜底"才到位

### 陷阱 2："检索分数最高的最可信"

- **✅ 真相**：相似度 ≠ 可信度。转载文档与官方原文语义几乎相同，分数分不出权威——权威靠入库元数据，不靠向量

### 陷阱 3："多数文档一致的就是对的"

- **✅ 真相**：同源转载伪造多数票——计票前先按 canonical hash 归并**独立信源**，Doc A/B 其实只有 1 票

### 陷阱 4："矛盾就删掉一份"

- **✅ 真相**：先归因。时间性冲突打版本标签（旧版留审计口径）、条件性伪冲突两份都合法——只有真事实冲突才进仲裁/淘汰

## 四、最佳实践

- **入库期防线优先**：`effective_date` / `authority_tier` / `superseded_by` 元数据是最便宜的仲裁（配 [知识入库流水线](../knowledge-ingestion-pipeline/README.md)）
- **仲裁结果落日志**：哪份胜出、依据哪条规则——可解释、可回放、可审计
- **高风险域不静默选边**：财务/医疗/法务置信度低 → 显式披露冲突或转人工（配 [RAG 超范围拒答](../rag-out-of-domain-rejection/README.md) 的 Deflect/Escalate）
- **度量口径**：冲突检测 P/R + 仲裁正确率 + 矛盾注入回归（counterfactual 红队测试）
- **姊妹题对照**：[相似文档消歧](../similar-doc-disambiguation/README.md)（多版本"区分"）/ [LLM 幻觉](../hallucination/README.md)（输出与源文档矛盾）

## 五、面试话术（30 秒 + 90 秒）

**30 秒版**：

> "不能直接丢给模型——LLM 面对冲突证据是 biased 裁判：多数从众、位置敏感、还会折中编造，2:1 的过时多数会赢过一份新政公告。正确做法是显式流水线：先归因，时间性冲突用入库元数据过滤，条件性伪冲突并列呈现，真事实冲突才仲裁；仲裁规则优先——时效、权威级、归并转载后的独立信源共识，裁不了再上 LLM-as-Judge，把元数据随文档给它、要求引证并允许输出'无法裁决'；高风险场景低置信度就显式披露冲突或转人工，绝不静默选边。"

**90 秒版**（补纵深）：

> "先给结论：不能隐式信任模型自行判断，但要区分'隐式信任'和'显式仲裁'两件事。
> 为什么不能直接丢：ICLR 2024 的实证研究（Adaptive Chameleon or Stubborn Sloth）表明 LLM 面对冲突证据有系统性偏差——多数从众，上下文里 2:1 的多数派显著带偏答案，哪怕多数是同源转载；位置偏差，调换文档顺序答案可能翻转，长上下文还有 Lost in Middle；模型看不到来源权威级，检索分数只度量语义相关不度量可信；最糟的是它默认自信单选，不会自发说'文档有矛盾'，还可能编出'7-15 天'这种折中答案。
> 处理框架是四层防线：L1 入库预防最便宜——effective_date、authority_tier、superseded_by 元数据，加 canonical hash 归并转载，防止伪造多数票；L2 检索后检测——成对 NLI、LLM 事实抽取比对、Self-Consistency 采样；L3 仲裁——规则优先：时效 > 权威 > 独立信源共识，规则裁不了才 LLM-as-Judge，元数据必须随文档进 Prompt，要求引用证据、输出置信度、允许'无法裁决'；L4 生成端——高置信度直答，条件性伪冲突并列呈现，低置信度显式披露冲突，高风险域转人工。
> 归因先行很关键：EMNLP 2024 综述把冲突分 inter-context / context-memory / intra-memory 三类，本题是 inter-context，再细分时间性、条件性伪冲突、真事实冲突——旧政策不是删掉而是打废止标签留审计，境内境外两条规则都对就该并列。全程仲裁结果落日志，可解释可回放。"

**延伸追问（含答案）**：

1. **Q：旧版本文档要不要直接删？**
   A：不删，打 `superseded_by` 废止标签 + pre-filtering 默认过滤。审计要历史口径，且用户明确问"2024 年政策是什么"时要能召回——与相似文档消歧"要区分不要删除"同一原则。
2. **Q：NLI 和 LLM 事实抽取检测怎么选？**
   A：NLI 便宜快但对数字/日期不敏感（120万 vs 1200万可能判不出 contradiction）；LLM 抽三元组比对能抓细粒度冲突但贵。工程上 NLI 全量粗筛 + 抽取比对只对高分候选跑。
3. **Q：模型参数记忆和检索文档也矛盾（context-memory 冲突）怎么办？**
   A：RAG 场景一般应信上下文——这正是引入检索的意义；但要防 Prompt 注入伪造"证据"，权威级过滤 + 来源白名单兜底。模型"固执"拒信新文档时，在 Prompt 中显式声明"以提供文档为准"。
