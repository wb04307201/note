### 写作要求

- 版本轴文章：封面标注 **LTS / 非 LTS** + 发布时间 + 前一版本链接（编年史连续性）
- 特性轴文章：封面标注**引入版本 + 成熟版本**（如 sealed：16 预览 → 17 正式）
- 新版本发布（如 java-27）落地时：建 `java-NN/` + 更新本 README 目录导航 + 检查特性轴是否需要更新「成熟版本」标注
- 特性与 `03-concurrency/`（虚拟线程属并发深钻）、`02-jvm/`（GC 演进属 JVM 原理）有边界——版本目录只做「该版本引入了什么」的索引级覆盖，深钻放对应专题目录并互链

### 反模式

- ❌ 特性深钻内容塞进 `java-NN/`（应放特性轴，版本目录只索引）
- ❌ 版本文章无 LTS 标注（工程选型关键信息缺失）
- ❌ 特性文章不写「引入 → 预览 → 正式」版本链（V2 = 0 分）
- ❌ 逐版本流水账无「是否值得升级」判断（V3 = 0 分）
