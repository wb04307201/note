## 1. 意图与背景（Why）

3 个 meta-skill 在 IT 领域已验证（2026-09-03 66/66 场景 + `note-temp` 借 KB demo），但**领域通用性从未测过**：既有测试全部用 IT 内容（HashMap / CAP / RAG…），验证的是路径/调用通用性（NOTE_DIR、模块运行时发现），不是概念层通用性（`STARTUP-NEW-KB.md` §8 的 note-temp 也是 IT 内容）。

本测试回答：**换一个知识领域，3 个 skill 还能不能用？哪里卡住？** 并以 IT 领域为对照组，保证改进「只能变宽，不能变差」。

## 2. 目标 / 非目标 / 反目标

**Goals**
- G1 量化非 IT 领域可用性：~36 个场景，每场景 PASS / DEGRADE / FAIL
- G2 耦合点归因（三角定位）：同一摩擦点 ≥ 2 个非 IT 域复现 → 真耦合确认；仅 1 域 → 按 §6 规则定级
- G3 驱动改进：P0（真 bug）/ P1（参数化措辞）修复，并经 IT 回归验证
- G4 规模阈值验证：中 KB（~80-120 篇）触发采样 / 先例对照 / 系列 / 分批等规模启发式

**Non-goals**
- 不重跑 66 场景全量（IT 回归抽样 ~10 决策场景 + Safeguards）
- 不回归 CI workflows 全链（仅改动涉及处）
- 测试 KB 不入本仓库 git（外部临时目录）
- Phase A 测试期间不修改 skill（先测后改，证据与修改分离）

**Anti-goals（出现即测试失败）**
- 全局替换式「泛化」稀释 IT 特化价值（如「面试话术」→「要点」）
- 把单域怪癖当 skill bug 修（过度泛化）
- 结论无场景证据（只有定性印象）

### 4.4 契约完整性两步策略（builder check #7）

测试 KB **按文档最低契约建**（STARTUP-NEW-KB §2.2 + §1.5）。当流程因「契约未声明的必需配置」静默失效时（已知 `STARTUP-NEW-KB.md` §5 有漂移——仍称 v3.x「尚未实施」并推荐 `12.interview/` 命名 workaround，实际 skill 已 pointer 化）：

**发现三分类**（报告记账维度）：① skill 缺陷 ② 契约-文档缺口 ③ 领域失配（词汇/场景错位）

## 6. 判定标准

**判定模型：规则溯源（rule-trace）**（builder check #8 · 用户裁定：不按执行者直觉判定，按规则判定）——几层/位置的对错由**规则库**推导，不由事后观感决定。「符合几条规则 → 几个预案 → skill 基于预案综合出最终方案」：

| 层 | 内容 | 冻结时机 |
|----|------|---------|
| **规则库** | 测试 KB 的 `SPEC.md`（领域谓词定义：「认证常考」「叙事价值」等）+ skill 决策树通用规则（Phase 0 拆分信号 / Phase 3 位置 / Phase 4 方式 / §1.8 先例覆盖） | 建库时编写，**跑场景前冻结**，随规则溯源表签认 |
| **输入属性** | 每场景 1-3 个显式假设（预估行数 / 考试价值 / 叙事价值 / 先例条件） | 规则溯源表列出，签认时可被否决 |
| **命中 → 预案** | 按输入属性推导命中的规则清单（带编号）；符合几条规则就有几个预案 | 由规则库机械推导，非人工发挥 |
| **最终方案** | skill 基于预案综合出的最终几层 / 位置方案 | skill（被测对象）输出 |

**PASS = 双条件**：
1. **一致性**：最终方案与命中规则推出的预案一致（规则冲突按文档优先级裁决；**优先级未定义 → 记「规则缺口」发现**，不算 skill 的错）
2. **可追溯**：决策链可回溯到具体命中规则与输入属性（"为什么双层？→ 认证常考 + 深度原理 → 规则 R2"）——答案蒙对但推理链断不计 PASS

| 级别 | 定义 | 去向 |
|------|------|------|
| PASS | 一致 + 可追溯（含合理降级：谓词不适用时显式声明并跳过 = 命中「降级预案」） | — |
| DEGRADE | 结论与规则一致但词汇/流程错位（如咖啡域输出「面试话术」），或谓词强行翻译致语义漂移 | P1 措辞参数化 |
| FAIL | 结论违反命中规则 / 决策链不可追溯 / 卡死 / 引用不存在路径 | P0 候选 |

**诚实边界（残余判断）**：
- 规则谓词的**输入属性仍需判定一次**（「手冲闷蒸」算不算高认证价值）——唯一残余判断，已收敛到规则溯源表假设列，签认时可否决
- 规则谓词无法在域中表达（「面试价值」在咖啡域）→ 假设列显式翻译（「= SCA 认证常考」），翻译错位记「领域失配」发现
- 表外意外发现不受表约束，进「意外发现」记账区
- **预判**：现行 skill 决策树无规则编号、输出不附命中链——「可追溯」大概率是 Phase B 首个改进项（规则编号化 + 输出附命中链），初测大面积 DEGRADE/FAIL 属预期而非事故

**归因与严重度分工**（builder check #6 修正）：**三角定位定置信度，严重度定优先级**——

- FAIL 在任意域出现 → **P0 候选**（先做根因判定：skill 缺陷 / 契约缺口 / 域怪癖，见 §4.4 三分类）
- ≥ 2 域复现的 FAIL / DEGRADE → 确认真耦合（FAIL=P0 必修，DEGRADE=P1）
- 仅 1 域复现的 DEGRADE → P2 记录观察
- **独有压力点例外**：域间压力点刻意不重叠（如 §1.5 角色机制只有咖啡在测），因此单域 FAIL 若落在独有压力点上，**仍是有效耦合证据**，不得因"无法三角"降级
- Phase B 修复清单最终由用户批准——scope 由用户在该闸口控制

## 8. 设计决策（builder 可直接采用，不必回问）

1. 测试域 = 咖啡 / 投资 / 健身（压力点互补：认证+叙事 / 无考试+数字断言 / 计划设计+无认证）
2. 无现成材料 → 全部生成式；咖啡中 KB 分 4-6 批，每批 ≤ 25 篇控制上下文
3. 测试 KB 放 `D:/developer/IdeaProjects/note-kb-test/`，不入 note 仓库 git
4. 本设计文档与报告放 `.claude/skills/`（延续 `test-scenarios.md` / `test-results-summary.md` 先例；是否 commit 由用户决定）
5. 场景执行用**真实 skill 调用**（Skill 工具 + NOTE_DIR 指向测试 KB），不模拟决策——2026-09-03 的遗留待办正是「跑真实 Skill 调用」
6. IT 回归抽样而非全量：决策类场景对改动最敏感，实施类由 note-temp 冒烟兜底
7. 改进模式走 v3.x 参数化老路（§1.5 角色自描述 / §8 词表 / `<module>/SPEC.md`），不全局替换领域词汇
8. **builder check 裁决**：R 沉淀类场景止于 Phase 5 且对本仓库 read-only（#1）；选项/交互按 §5.5 脚本协议（#2）；KB 状态 = 固定序累积 + git tag 快照（#3）；角色词汇按契约 `type=interview`（#4，设计稿已修正）；R0 前置基线快照（#5）；三角定位定置信度而非严重度（#6）；契约完整性两步策略 + 发现三分类（#7）；**判定用规则溯源双条件（#8，用户裁定：按 SPEC.md 规则判定，不按执行者直觉）**

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 生成内容质量不齐干扰归因（内容问题 ≠ skill 问题） | 每批生成后 note-health 单篇评分抽查；内容问题单独记账 |
