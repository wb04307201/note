## ① 何时生成

SPEC（L0 / L1 / L1x）只在这 4 个触发下生成新节或新行:

| 触发 | 产出 | 现有出处 |
|------|------|---------|
| 建新 KB | L0 SPEC（7-9 节） | [STARTUP §2.2](../../../STARTUP-NEW-KB.md)（指入） |
| 建新模块 | L1 SPEC | [MODULE-CREATION Step 2](MODULE-CREATION-SPEC.md)（指入） |
| 建 L1x（§7 三信号任 2） | 子目录 SPEC | [SPEC §7](../../../../SPEC.md)（指入） |
| **增/删角色模块** | §1.5 行 + §1.6 谓词同步 | **缺失,本设计补**（步骤见下） |

**增/删角色模块 → §1.5 行 + §1.6 谓词同步**（本设计补,原无出处;角色结构见 [`SPEC.md §1.5 / §1.6`](../../../../SPEC.md)）:

- **增角色模块**: ① §1.5.1 角色清单加一行（`| <模块名> | <type> | <备注> |`）;② §1.5.2 语义表核对 type（depth / interview / story / other 四类已齐,仅新 type 才补行）;③ §1.6 谓词表逐行核对「本 KB 定义」列口径受新角色影响处（如新增 interview 模块 → "考试价值高" 口径可收窄到该模块）,只改定义列——「影响规则」列的 R# 归属以 rule-catalog 为单源,不在本步改
- **删角色模块**: ① §1.5.1 删对应行;② §1.6 中以该角色为口径的谓词改写定义或回退默认语义（降级说明见 SPEC §1.6）;③ 跑 ④ 改后三查

## ② 怎么生成

**生成顺序**（新 SPEC 从零生成时按序写节）:

`§1 命名` → `§2 commit` → `§3 互链` → `§1.5 角色` → `§1.6 谓词` → `§8 词表` → `§9 契约`

**每节模板**（收编指入,不在本文件复制）:

- **L0**（建新 KB）: [STARTUP §2.2 骨架表](../../../STARTUP-NEW-KB.md)（9 节表格 + 最低要求列）
- **L1**（建新模块）: [MODULE-CREATION Step 2](MODULE-CREATION-SPEC.md)（模块定位 / 从 L0 继承 / D1-D5 / 子目录约定 / 链回 §7）
- **L1x**（建子目录 SPEC）: [SPEC §7 三件套](../../../../SPEC.md)（子目录定位 + 继承声明 + 专属维度 + 互链 + 反模式,~60 行）

**最低内容要求**沿用现有表:各节最低行数 / 词条数见 [STARTUP §2.2](../../../STARTUP-NEW-KB.md)「最低要求」列（如 §8 ≥ 5 词条、§1.6 至少 3 行谓词）——**不在本文件重复维护**（防 Mistake 15）。

## ③ 何时修改

统一修改事件清单（原散落各处）:

| 事件 | 改哪些节 | 现有出处 |
|------|---------|---------|
| 角色变更（增/删角色模块） | §1.5 + §1.6 | **缺失,本设计补**（= ① 增/删角色步骤,不重复） |
| 结构重构（拆/合/迁移） | §1 路径 + §8 词表 | [SPEC §8.4](../../../../SPEC.md)（指入） |
| rule-catalog 规则变更 | 各 KB §1.6「影响规则」列核对 | **缺失,本设计补**（见下） |
| frontmatter 类型增删 | §4 | **缺失,本设计补**（见下） |
| 体检 P1 契约类发现 | 对应节 | **缺失,本设计补**（见下） |
| L1.5 合并/拆分 | §7 | 部分（补「何时并回 L1」,见下） |
| 评分维度校准 | §5 | auto-calibrate 指入（[SPEC §5](../../../../SPEC.md)） |

**rule-catalog 规则变更 → §1.6「影响规则」列核对**（本设计补）:

- **触发**: [`rule-catalog.md`](rule-catalog.md) 增删 R# / 改规则语义 / 改谓词归属时
- **步骤**: ① 打开本 KB `SPEC.md §1.6` 谓词表;② 逐行核对「影响规则」列——R# 已删 → 移除该编号;R# 新增且依赖本谓词 → 补列;③ 谓词本身增删 → 走 ①「增/删角色模块」同步步骤;④ 无 §1.6 的 KB 不需核对（默认语义降级）
- **边界**: 只核对「影响规则」列（R# 归属）;「本 KB 定义」列只随 KB 口径变化改,不随 catalog 语义改

**frontmatter 类型增删 → §4**（本设计补）:

- **触发**: frontmatter 类型（module / question / story）新增或废弃时
- **步骤**: ① 改 [`SPEC.md §4`](../../../../SPEC.md) schema（新类型加 schema 块 + 示例;废弃类型标废弃 + 迁移说明）;② 对照 §1.5.2 类型语义表评估是否补行（frontmatter 类型与角色类型有映射:question↔interview、story↔story）;③ skill 侧 frontmatter 生成 / 校验经 §9.1 契约指向 §4 自动生效,skill 主体不改;④ 跑 ④ 改后三查

**体检 P1 契约类发现 → 对应节**（本设计补）:

- **触发**: `note-health` 体检报 **P1 契约类**问题（pointer 漂移 / §1.5 缺行 / §1.6 口径漂移 / §8 词表死链 / frontmatter 缺口等）
- **步骤**: ① 按发现类型定位对应节——pointer 类 → §9;角色类 → §1.5;谓词类 → §1.6;词表类 → §8.4;frontmatter 类 → §4;评分类 → §5;② 按 ④ 修改协议改（顺序 / 版本日志 / 三查）;③ 修复后复跑对应体检项确认归零
- **边界**: P1 = 契约类必修;修复默认只动 KB SPEC 侧,需动 skill 主体时走 ④ 顺序（先 SPEC 后 skill）

**L1.5 合并/拆分（补「何时并回 L1」）**: [`SPEC.md §7`](../../../../SPEC.md) 已有「何时新建 L1.5」;何时**并回 L1**——L1.5 与 L1 读者重合（评审 + 写作者同一批）且行数差缩到 ~2 倍以内,或 L1.5 内容已稳定不再独立演化时,合并入 L1 对应章节（v2.1 起 12 / 13 的 L1.5 即按此并回）。判定口径 = SPEC §7「按模块规模与读者重合度判定」。

## ④ 怎么修改

- **顺序——先 SPEC 后 skill**: 改动前先看 [`SPEC.md §9.3`](../../../../SPEC.md) 维护协议（收编为索引）:先看 §9.1 责任矩阵确认改在哪;新增 pointer 引用但 SPEC 缺章节时**先补 SPEC + commit,再改 skill**（避免 pointer 漂移）
- **版本日志**: 每次改 SPEC 后在该文件「版本日志」小节补一行（`- YYYY-MM-DD vX.Y <一句话变更>`,一行/版本）;**L1 模板自此加轻量版本日志小节**（L1.5 模式推广;尚无该小节的 L1 在下次修改时补上）
- **改后三查**（类比 [`CLAUDE.md`](../../../../CLAUDE.md)「Skill 修订 Safeguards」）:
  1. **锚点审计**: grep 跨文件 `Phase N` / `§N` 引用仍解析
  2. **派发 smoke**: 3 类典型原话验证 skill / phase 路由不变（"X 沉淀到哪" / "扫一遍 KB" / "查 KB"）
  3. **链接校验**: `python .github/workflows/scripts/check-broken-links.py <改动文件>` 总计 0
- **禁忌**:
  - 同文件重复维护等价表格（[mistakes.md Mistake 15](mistakes.md)）——本文件对既有节只放一行摘要 + 链接
  - 数字硬编码（如 "47 节"）——声明处附 `find` 校对日期 + 统计命令
  - 无 `find` 校对的篇数 / 节数声明
