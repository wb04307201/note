## 1. 意图与背景（Why）

R1（2026-11-13~16，咖啡/投资/健身 3 域）验证的是**skill 机制层**域中立性（24 PASS + 2 DEGRADE + 0 FAIL），但那轮测试**早于规则引擎落地**——`rule-catalog.md`（R1-R25 单源）+ precipitation Phase 3/4 三段式（命中表→预案→综合裁决带溯源链）+ `SPEC.md §1.6` 谓词层是 2026-11-18~19 才迁进 skill 的，只做过 IT 侧 R0 回归（10/10），**从未在非 IT 域跑过**。

R2 回答两个问题：
1. **规则引擎首考**：换 3 个全新领域，三段式决策 + R# 溯源链还能不能正确运转？规则语义（R1-R25）在域中立表述下有没有隐藏的 IT 假设？
2. **R1 遗留闭环**：R1 报告明示「P2 待办（下轮）」7 项，本轮消化（其中 V3 已于 7aa6a57 顺手修复，本轮复验闭环，见 §6）。

并以 IT 为对照组（R0 冻结基线重放），保证「只能变宽，不能变差」。

## 2. 目标 / 非目标 / 反目标

**Goals**（「通用、稳定、可用」的可验收化）
- G1 **通用**：26 个非 IT 场景（12+8+6）**0 FAIL**；跨域复现的 DEGRADE 修复后复测转 PASS
- G2 **稳定**：R0 十例对照冻结基线 **10/10 不变**；Safeguards 三查全过
- G3 **可用**：所有降级路径显式声明不卡死（R23/R16）；三段式输出完整（命中表/预案/裁决三段齐全 + 溯源链 R# 可解析到 rule-catalog）
- G4 **引擎溯源质量**：每沉淀类场景记录三段式输出原文，溯源链断/编造 R# = FAIL 可追溯
- G5 规模启发式在**单角色中 KB**（有 story 无 interview）下行为正确（采样/系列/先例/分批不退化）
- G6 P2 背包闭环（6 项修复 + M3 对 V3 的跨域复验）+ F0 规则语义冲突修复

**Non-goals**
- 不重跑 R1 的 26 个场景（coffee/invest/fitness 已结案留档）；R1 测试 KB 不动
- 不重跑 66 场景全量（IT 对照走 R0 + Safeguards + note-temp 冒烟）
- 不回归 CI workflows 全链（仅改动涉及处）
- 测试 KB 不入本仓库 git（外部临时目录）

**Anti-goals（出现即测试失败）**
- 全局替换式「泛化」稀释 IT 特化价值（同 R1）
- 把单域怪癖当 skill bug 修（同 R1）
- 把 R1 已知 P2 项重复报为「新发现」（记「已知-已排期」，不重复计数）
- 结论无场景证据（只有定性印象）

### 4.4 契约完整性两步策略（沿用 R1 §4.4）

## 6. 判定标准

**沿用 R1 规则溯源双条件**：① 一致性（最终方案与命中规则推出的预案一致）② 可追溯（决策链可回溯到具体 R# 与输入属性）。PASS / DEGRADE / FAIL 定义、残余判断诚实边界、三角定位归因——全部沿用 R1 §6。

**R2 强化（引擎专属）**：
- **溯源链完整性** = 可追溯的硬化：三段式输出缺段、溯源链断、引用 rule-catalog 不存在的 R#（编造）→ 直接 FAIL（可追溯），不论最终方案对错
- **R# 域中立性核查**：每场景对命中的 R# 语义做一次「IT 假设残留」检查（判据里是否暗含 IT 词汇/结构假设）——残留记「领域失配」发现
- **P2 已知项不重复计数**：H12 等预期复现 R1 已知 DEGRADE 根因（V1 已修，若仍现 = 修复不彻底，记新发现）；**V3 已修（7aa6a57），M3 改为跨域复验**（预期 PASS）

### 6.1 冲突探针与预注册发现 F0（builder check #1 裁定）

**F0（预注册发现，已确认）**：`rule-catalog.md` 三处语义不一致——R23 规则正文「无 interview/story 角色模块」（双缺才降级）vs R23 谓词「任一缺失即命中」vs `note-precipitation-planning/SKILL.md` 选项级排除（「无 interview 角色 → 排除 R8/R4」，story 门控存活）。R9 预案硬编码 `<interview>` 层位，单角色 KB 机械推导不出唯一终态。**「语义单源」完整性破坏 = P1**，Phase B 修。

**设计者裁定（角色比例降级，签认时可否决）**：R23 只降级**缺失角色所门控**的规则——KB 有 story 无 interview 时：R8/R4 等 interview 门控规则失效，R6/R9 等 story 门控存活；R9 在单角色 KB 缺省 interview 层（`<depth>/<story>`，commit=2）；R10 落位按「先例覆盖」语义取**先例系列所在栏目**（`<interview>/<现象>-troubleshooting` 的 interview 落位是 IT 残留）。依据：SKILL 选项级排除代表意图；把叙事内容从**已声明的** story 模块降级扔进 depth 单文件语义上不成立。

**冲突探针行 = H3 / H7 / L2 / M5**（同构输入跨域对照）。判定：
- 输出 = 裁定语义（带完整溯源）→ **PASS**
- 输出 = catalog 字面全降级（带完整溯源）→ **DEGRADE**（记 F0 证据，Phase B 修后复测转 PASS，计入 G6）
- 溯源链断 / 编造 R# → **FAIL**
- 同构输入跨行处置不一致（如 H3 存活而 L2 全降级且无谓词差异说明）→ **FAIL**（稳定性违背）

**P2 背包（R1「下轮」遗留，Phase B 必做；V3 已核销）**：
1. S3 Phase 1.6 单向链接口径分层 2. S2 回链 checklist 强化 3. K5 tags↔§8 口径说明 4. V4 Phase 5.5 域模板位 5. V5 13.story 路径残留清理 6. note-temp 链接脚本同步（R2-S2 顺手做）· ~~V3~~ 已修（7aa6a57），由 M3 复验闭环

**验收（对应 G1-G6）**：26 场景 0 FAIL；R0 十例 10/10；Safeguards 全过；降级全显式；三段式+溯源链全完整；P2 六项修复 + M3 复验闭环；F0 修复后冲突探针行全 PASS。

**反目标守则**（改进时必须遵守）：同 R1——不许全局替换稀释 IT 特化；改动走 §1.5/§1.6/§8/`<module>/SPEC.md` 参数化老路；改完跑 Phase C 回归。

## 8. 设计决策

1. **域 = 健康 / 法律 / 音乐**（用户选定方向 A：压力点多样性优先；具体三域为本设计按互补性选定）：角色不对称+时效 / 强编号+版本 / 无判定软域
2. 健康 KB 刻意**只设 story 不设 interview**（单角色不对称）——R1 的 coffee 是双角色，这轮补不对称盲区
3. 生成式建 KB、放 `note-kb-test/`、分批 ≤ 25 篇、git tag 快照——沿用 R1 结论，不再重议
4. 判定沿用规则溯源 + R2 强化溯源链硬校验（引擎首考的核心增量）
5. P2 背包进 Phase B 必做（R1 报告已裁定「下轮」；测试预期复现项记「已知-已排期」不重复计数）
6. 场景规模 12+8+6=26 与 R1 对齐（可比性 + 覆盖三 skill 全决策面）
7. IT 对照 = R0 重放（而非旧 66 场景）——R0 是规则引擎冻结基线，对照意义最大
8. 测试 KB 契约最低配 + 两步策略 + 发现三分类——沿用 R1 §4.4
